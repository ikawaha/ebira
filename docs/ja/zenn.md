title: Zenn に書き出す（β）

ノートを、[Zenn](https://zenn.dev) の記事として書き出せます。Zenn と連携した GitHub のリポジトリに、記事のファイルと画像を書いて push します。Zenn はそのリポジトリから記事を取り込みます。

> **β です。** 書き出しの形や設定は、これから変わることがあります。
>
> **Zenn の GitHub 連携を使っている場合だけ使えます。** ebira が書くのは GitHub のリポジトリで、Zenn の Web のエディタには書きません。Zenn のダッシュボードで GitHub のリポジトリを連携していないと、push しても Zenn に記事は出ません。Zenn の Web のエディタで書いている記事を、ebira から書き直すこともできません。

## 必要なもの

ebira は Zenn にも GitHub にも直接つながず、サーバーの中から `git` のコマンドを呼んで、clone・コミット・push をします（GitHub の API キーや Zenn のキーは要りません）。そのため、次のものが要ります。どれも、ebira のサーバーが動いている機械のものです（ブラウザの機械ではありません）。

- **git**: サーバーから見える `git`。macOS では Xcode の Command Line Tools か Homebrew の git、Windows では Git for Windows。デスクトップアプリが起動したサーバーは PATH が短いので、`/usr/bin/git` など決まった場所にあるものが使われます。サーバーが git を見つけられないときは、書き出しのダイアログでそう知らせ、書き出せないようにします（入れ方は下の「git を用意する」）。
- **GitHub への push の認証**: 入力を求めずに通る方法。SSH の鍵（ssh-agent や 1Password の SSH agent）、または HTTPS の credential helper。ebira はパスワードを聞かないので、`git push` が端末で聞いてくるなら書き出せません。
- **コミットする人の名前とメール**: git の設定の `user.name` と `user.email`。コミットに署名する設定なら、それも入力なしで通ること（1Password の署名なら、書き出すたびに承認の画面が出ます）。
- **ネットワーク**: サーバーの機械から GitHub に届くこと。git の 1 つのコマンドは 2 分で打ち切ります。
- **Zenn の GitHub 連携**: Zenn のダッシュボードで GitHub のリポジトリを連携してあること（Zenn の GitHub アプリがそのリポジトリを読めること）と、Zenn が取り込むブランチ。これが無いと使えません（下の「用意する」）。

### git を用意する

ebira のサーバーが動いている機械のターミナルで、順に確かめます。

1. **git があるか**: `git --version` で版が出れば入っています。無ければ入れます。
   - macOS: `xcode-select --install` で Xcode の Command Line Tools を入れます（`/usr/bin/git` が使えるようになります）。Homebrew の git（`brew install git`）だけだと、デスクトップアプリが起動したサーバーからは見つからないことがあるので、Command Line Tools も入れておくと確実です。
   - Windows: [Git for Windows](https://gitforwindows.org/) を入れ、デスクトップアプリを起動し直します。
   - Linux: ディストリビューションのパッケージで入れます（`sudo apt install git` など）。
2. **コミットする人**: `git config --global user.name "名前"` と `git config --global user.email "メール"` を設定します。
3. **push の認証**: `git ls-remote git@github.com:you/zenn-content.git`（あなたのリポジトリの URL）が、パスワードやパスフレーズを聞かずに一覧を出せば大丈夫です。
   - SSH の URL なら、GitHub に公開鍵を登録し、鍵を ssh-agent（や 1Password の SSH agent）に入れておきます。
   - HTTPS の URL なら、credential helper（Git Credential Manager や macOS のキーチェーンなど）に GitHub の認証を覚えさせておきます。

用意できたら、書き出しのダイアログを開き直します。git を入れたあともダイアログが git を見つけられないときは、サーバー（デスクトップアプリ）を起動し直してください。

## 用意する

1. Zenn のダッシュボードで GitHub のリポジトリを連携します（Zenn の「GitHub リポジトリで Zenn のコンテンツを管理する」の手順のとおり）。ここで連携したリポジトリとブランチが、ebira の書き出す先です。
2. 歯車のメニューの「設定…」の「連携」のタブの「Zenn（β）」に、リポジトリの URL（`git@github.com:you/zenn-content.git` など）を書いて保存します。ブランチは、Zenn が取り込むブランチがリポジトリの既定のブランチでなければ書きます。Zenn のユーザー名を書くと、記事へのリンクが使えるようになります。設定ファイルなら `zenn_repo`・`zenn_branch`・`zenn_user` です（[設定](settings.md)）。保存するとすぐに使えます。

ebira は、そのリポジトリを自分用に clone して、この端末の状態の場所（`~/.local/state/ebira/…/zenn/`）に置きます。あなたが手元で使っている作業場所には触れません。git はあなたの設定のまま使うので、認証・SSH の鍵・コミットの署名もそのとおりに動きます。

## 書き出す

プレビューの右上の、右上へ矢印の出る Z のボタンで「Zenn に書き出す」のダイアログを開きます。

- **絵文字**: 記事のアイキャッチの絵文字。ランダムに選んであるので、横の矢印で選び直すか、1 つ入力します。
- **種類**: Tech（技術記事）か Idea（アイデア）。
- **トピック**: カンマ区切りで 5 つまで。最初はノートのタグから作ります（小文字にし、記号や空白を含むもの（`C++` など）は外します。`cpp` のように書き直してください）。
- **公開する**: 外すと下書きです（最初は下書き）。

「書き出す」で、ノートを `articles/<ノートの ID>.md` に、画像を `images/<ノートの ID>/` に書き、コミットして push します。まもなく Zenn に反映されます。題名はノートの題名です（Zenn は 70 文字まで）。

記事のファイルの名前（slug）は、ノートの ID です。ノートの ID が Zenn の決まり（英小文字・数字・`-`・`_` の 12〜50 文字）に合わないとき（手で短い ID を付けたときなど）は、最初に書き出すときに slug を聞きます。ebira が付けるランダムな ID は合います。slug は記事の URL になるので、一度書き出したら変えられません。ほかのノートの ID や、ほかのノートの記事の slug も使えません。

もう一度書き出すと、同じ記事を書き直します。前に選んだ絵文字・種類・トピックが残っています。

## 本文の変わるところ

- ノートの画像は記事の画像になります。Zenn が受け付けるのは 3MB までの PNG・JPEG・GIF・WebP なので、ほかの画像があると書き出せません。
- 画像でないファイル（PDF など）へのリンクは、Zenn に置けないので、リンクの文字だけになります。
- ほかのノートへのリンクは、そのノートを公開の記事として書き出していれば、その記事へのリンクになります。そうでなければ文字だけになります。
- 変えたことは、書き出したあとのダイアログに出ます。コードの中は変えません。

## 目印

書き出したノートには、一覧の行の右端に、右上へ矢印の出る Z の印が付きます。下書きは薄く出ます。プレビューの情報の行の末尾には「Zenn（下書き）」か「Zenn（公開中）」と出て、押すと Zenn の記事を開きます（Zenn のユーザー名を書いたとき）。TUI では行の後ろとプレビューの情報の行に `⇗` を出します。印は、Zenn のリポジトリを設定している間だけ出ます。

書き出したあとにノートの題名か本文を変えると、記事はまだ前の内容のままです。そのあいだ、一覧の印とプレビューの書き出すボタンの右上に赤い点が付きます（TUI は `⇗*`）。もう一度書き出すと消えます。タグを変えただけでは付きません（トピックは書き出したときのものを使うため）。画像のファイルだけを差し替えたときも付かないので、そのときは書き出し直してください。

## 気をつけること

- GitHub 連携には限定公開がありません。公開した記事は誰でも読めます。下書きに戻すことはできますが、記事を消すのは Zenn のダッシュボードで行います（リポジトリからファイルを消しても、Zenn の記事は残ります）。
- リポジトリの記事のファイルを、ebira が書いたあとに GitHub などで直していると、上書きしてよいかを聞きます。
- private のノートブックのノートは、書き出す前に確かめます。
- 書き出すのは人だけです。AI のツールにはしていません。
- 書き出した記事のことは、ノートのファイルの `zenn:` に残ります（ノートと一緒に同期されるので、ほかの端末からも同じ記事を書き直せます）。書き出しても、ノートの更新日時は変わりません。
