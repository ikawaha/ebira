---
title: パスキー
tags: [guide, safety]
---
既定では、このコンピューターから Web UI を開けば、だれでもノートを見られます。パスキーで守るには、次のようにします。

1. `ebira auth passkey` で、パスキーを登録するページを開く
2. 設定ファイルに `auth: passkey` を書き、サーバーを起動し直す

そのあとは、Web UI を開くとパスキーでログインを求めます。TUI とコマンドは、Web UI で承認してつなぎます。

- 非公開を外す・履歴を見る・ゴミ箱を空にする・サーバーを起動し直すなどの大事な操作では、パスキーをもう一度求めます。
- パスキーは歯車のメニューの「パスキーの管理…」で足し・消せます。
- パスキーを無くしたら、`ebira auth reset` で消して登録し直します。
- MCP は AI のための入り口なので、パスキーは求めません（private のノートブックは見えません）。

## 守れること、守れないこと

- パスキーを使わなければ、ログインはありません。サーバーは localhost（と `-addr` のホスト）宛てのリクエストだけに答え、ほかのサイトの Web ページからノートを変えるリクエストは拒みます。サーバーは手元のマシンで動かしてください。
- REST API へのリクエストはすべてあなたからのものとして扱うので、手元で `curl` を実行できる AI エージェントは、あなたとして振る舞えます。パスキーはこれを防ぎます。ログインしていないリクエストは断り、AI の入り口の MCP は変わりません。
- デスクトップアプリは、自分のサーバーのページからのメッセージだけを受け付け、ノートのリンクはウインドウの中ではなくブラウザで開きます。別のコンピューターのサーバーのアドレスを選ぶと、そのサーバーのページにクリップボードへの書き込みと、ブラウザでリンクを開くことを任せることになります。信頼できるサーバーだけを選んでください。
- ノートブックの種別による制限は、MCP もアシスタントも含め、ebira の API を通るすべての AI に効きます。ただ、ノートのファイルを直接読めるプログラム（ファイルを読める AI エージェントなど）は防げません。`private` は「AI に見せない」という目印で、暗号化ではありません（Claude Code からファイルを遠ざける方法は [AI と使う](ai.md) にあります）。
