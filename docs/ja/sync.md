ノートはただのファイルなので、ファイルを同期する方法なら何でも使えます。同期するのはノートだけで、検索の索引とサーバーの状態は各端末に残ります。

## Dropbox・iCloud Drive など

ノートのディレクトリを、Dropbox、iCloud Drive、OneDrive、Google Drive、Syncthing などが同期するフォルダに置きます。ebira 側の設定は要りません。

1. 1 台目では、初期設定で同期フォルダの中のディレクトリ（`~/Dropbox/notes` など）を答えます。同期フォルダであることが表示され、git は聞かれません。
2. 2 台目以降では、サービスがフォルダを同期し終えるのを待ってから、同じディレクトリを答えます。ebira はノートを見つけ、検索方式などの設定をそのまま使い、その端末で索引を作ります。端末ごとにパスが違ってもかまいません。それぞれの `notes_dir` が保存されます。

同期が終わる前に 2 台目で始めると、空のノートが新しく作られ、その設定が 1 台目の設定とぶつかります。

2 台で同じノートを直すと、サービスは一方の版を残し、もう一方を `3f9a… (MacBook's conflicted copy 2026-10-18).yaml` や `3f9a… 2.yaml` のようなコピーとして残します。ebira はそうしたコピーを、題名に `(conflict copy)` の付いた新しいノートにして隣に置き、元のノートと同じ内容なら消します。どちらの変更も無くなりません。

- 検索や索引がダウンロードを待たないよう、フォルダを手元に置いたままにしてください。Dropbox は *オフラインで利用可能にする*、iCloud Drive は *ダウンロードしたままにする*、OneDrive は *このデバイス上で常に保持する* です。選択型同期を使う場合は、どの端末でもこのフォルダを含めてください。
- 同期フォルダの中では git を使わないでください。サービスがリポジトリを壊すことがあり、別の端末から同期された変更をもう一度コミットしてしまいます。どちらか一方を使ってください。

## git

git を使うかは自由です。歯車のメニューの「git と同期」は、ノートがリポジトリに入っているときだけ出ます。これと `ebira sync`、設定ファイルの `git_sync: 10m`（その間隔で自動で同期する）は、どれもサーバーの中で同じことをします:

1. ノートのディレクトリの変更をコミットします（変えたファイルの一覧をメッセージに入れます）。
2. ブランチに上流のブランチがあれば、fetch してマージします。
3. push します。

すでにあるノートの同期を始めるには、1 回だけリポジトリにつなぎます（空のリポジトリか、ノートのあるリポジトリ）:

```sh
ebira sync -remote git@github.com:you/notes.git
```

リポジトリは、ebira が作る場合はノートのディレクトリそのものです。ノートのディレクトリを含む上のリポジトリでもかまいません。同期先のリモートとブランチは git の設定のままで、ebira は今のブランチの上流のブランチと同期します。変えるときは `git remote set-url` や `git branch --set-upstream-to` を使ってください。ebira はあなたの `git` を呼ぶので、認証・SSH の鍵・Git LFS の設定がそのまま使われます。パスワードは聞かないので、裏で同期させるには credential helper か SSH agent を用意してください。

マージは衝突で止まりません。2 台で直したノートは、この端末の版を残し、もう一方の版を、題名に `(conflict …)` と日時の付いた新しいノートとして隣に置きます。見比べて、要らない方を消してください。ノート以外のファイルが両方で変わったときはこちらの版を、片方で消えて片方で変わったときは変わった版を残します。もう一方の版はマージのコミットに残っています。手でマージして衝突のしるしが残ったノートは、ebira が知らせ、直前の正しい内容を表示し続けます。
